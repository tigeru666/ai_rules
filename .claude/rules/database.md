# 数据库规则

## 总原则
- 使用 GORM 进行数据库建模与访问
- 表名遵循现有风格：小写 + 下划线 + 统一前缀
- 系统管理相关表统一使用 `sys_` 前缀
- 不明确的字段、关系、状态不要臆造，先列假设

## GORM 约束
- 所有表结构必须与 GORM Model 保持一致
- 每个 Model 必须显式实现 `TableName() string`
- 每个字段的 `gorm` tag 必须明确 `column`、`type`、`not null`、`default`、`comment`
- 主键、索引、唯一索引必须显式声明
- 不直接把 Model 作为 API 响应结构返回

## 外键与级联
- 全局禁用外键约束
- 禁止使用数据库级联删除、级联更新
- 表关系在代码层维护，不依赖数据库外键
- 数据完整性校验、关联删除清理必须在 Service 层处理

## 注释要求
- 每张表都必须有表注释
- 每个字段都必须有字段注释
- 每个 Model 都必须写结构体注释，说明表用途
- 无外键、无级联的关系表，必须在注释中写清维护责任

## 命名与字段
- 表名统一小写下划线风格
- 关系表命名使用：`sys_实体1_实体2`
- 能用 `NOT NULL` 就不要 `NULL`
- 状态、类型字段使用明确枚举值，避免魔法值
- 金额字段使用 `decimal`，禁止 `float/double`
- 时间字段要明确列名、类型、自动填充策略

## 索引要求
- 主键、唯一索引、普通索引都要有明确用途
- 联合唯一索引优先显式命名，如 `uk_role_menu`
- 关系表即使无外键，也应通过联合唯一索引保证唯一性

## 特殊要求
- 无外键、无级联的关系表，注释需明确类似：
  - 分配关联时，必须在 Service 层校验两端数据存在
  - 删除任一端数据时，必须在 Service 层手动清理关系表
- 新增或修改表结构时，必须同时提供 migration 或 SQL
