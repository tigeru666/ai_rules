# OpenAPI 规则

## 总原则

- 所有公开接口都应维护 OpenAPI 描述
- OpenAPI 描述必须与真实行为保持一致
- 不允许注释与代码实现脱节

## Controller 要求

- Controller 负责维护 OpenAPI 接口注释
- 注释应覆盖接口用途、参数、鉴权要求、响应结构
- 参数来源必须准确标注：path / query / body / form
- 响应结构必须使用真实 DTO，而不是数据库 Model

## 接口设计约定

- 资源命名优先使用名词
- 列表查询默认优先使用 `GET + query/form`
- 复杂筛选条件可使用 `POST + body`
- 创建使用 `POST`
- 更新使用 `PUT` / `PATCH`
- 删除使用 `DELETE`

## 响应约定

- 成功响应使用统一响应结构
- 错误响应使用统一错误体系
- 分页接口响应至少包含：
  - `list`
  - `total`

## 文档要求

- 标签命名要清晰，按业务模块分组
- Summary 要简洁明确
- 参数说明应体现业务含义
- 鉴权接口必须标明安全要求
- 不得把废弃字段继续留在文档中
- 新增字段、新增接口、变更参数时，应同步更新 OpenAPI 描述

## 禁止事项

- 使用 `model.*` 作为对外响应结构
- 参数来源标错
- 注释与实现不一致
- 缺少鉴权说明
- 缺少分页字段说明
- 文档长期不更新
